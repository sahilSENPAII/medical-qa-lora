# Medical Question Answering: LoRA Fine-tuning of Llama-3.2-1B-Instruct

Fine-tune **unsloth/Llama-3.2-1B-Instruct** (an ungated mirror of Meta's
Llama-3.2-1B-Instruct) on the **MedQuAD** medical QA dataset using
**LoRA** (HuggingFace PEFT), then compare the base model against the fine-tuned
model with **ROUGE-L** and **BERTScore**.

Training was performed on a **Google Colab T4 GPU** (the M2 8GB CPU/MPS path
described below also works but is significantly slower).

---

## Project layout

| File | Purpose |
|------|---------|
| `config.py` | Shared settings: model id, prompt format, paths, device selection. |
| `train.py` | Load + format MedQuAD, configure LoRA, fine-tune, save adapter + loss curve. |
| `evaluate.py` | Generate base vs fine-tuned answers, score ROUGE-L / BERTScore, dump before/after samples. |
| `chat.py` | Interactive CLI chatbot using the fine-tuned model. |
| `smoke_test.sh` | End-to-end pipeline test on a tiny slice (50 examples). |
| `requirements.txt` | Pinned dependencies. |
| `outputs/` | LoRA adapter, `training_loss.png`, `metrics.json`, `sample_comparisons.json`. |

## Usage

```bash
# Smoke test (pipeline correctness, ~5 minutes)
./smoke_test.sh

# Full training (~20 min on Colab T4, ~1-2h on M2 Air)
python train.py

# Evaluate base vs fine-tuned
python evaluate.py

# Interactive chat with the fine-tuned model
python chat.py
```

Override defaults via environment variables (see `config.py`):

```bash
TRAIN_SIZE=1000 TEST_GEN_SIZE=30 python train.py
```

## How it works

**Data.** MedQuAD is loaded from `lavita/MedQuAD`. Rows with empty or trivially
short answers are filtered out, the set is shuffled with a fixed seed, and
2,000 examples are used for training with 200 held-out for evaluation. The
held-out QA pairs are saved to `outputs/eval_set.json` so evaluation scores
exactly what training never saw.

**Prompt format.** Uses the Llama-3 chat template via `tokenizer.apply_chat_template`
(system message + user question). Training appends the gold answer as the
assistant turn. Prompt tokens are masked with `-100` during tokenization so
loss is computed **only over the answer tokens**. Generation stops on both
`<|end_of_text|>` and the turn-end token `<|eot_id|>`.

**LoRA config.** `r=8`, `alpha=16`, `dropout=0.05`, targeting `q_proj` and
`v_proj` — standard, lightweight, ~0.1% of params trainable.

**Memory management.**
- fp16 base weights (~2GB instead of ~4GB in fp32)
- Gradient checkpointing enabled
- `evaluate.py` loads one model at a time — two 1B models never coexist

## Results

ROUGE-L and BERTScore-F1 on 50 held-out MedQuAD test examples (higher is better):

| Metric        | Base Instruct | Fine-tuned (LoRA) | Improvement |
|---------------|---------------|-------------------|-------------|
| ROUGE-L       | 0.1800        | 0.1954            | +8.5%       |
| BERTScore-F1  | 0.8392        | 0.8414            | +0.26%      |

The LoRA fine-tuning shifted the model toward the terser, clinical phrasing of
MedQuAD reference answers, improving lexical overlap (ROUGE-L) meaningfully and
semantic similarity (BERTScore) modestly. The Instruct baseline is already a
fairly strong starting point, so gains are smaller than they would be off a
non-instruct base.

The training loss curve is in `outputs/training_loss.png`.

## Limitations & disclaimer

- **Educational project** — outputs are **not medical advice**. A 1B model
  fine-tuned on a small subset will hallucinate and must not be used for real
  clinical decisions.
- Training subset deliberately kept small to fit Colab T4 free tier limits.
  Scaling `TRAIN_SIZE` and epochs improves quality but increases runtime.
